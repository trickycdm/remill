# Technical Decisions — remill

> The seeded decision log (an ADR-style record). Seeded from the build plan §6. Add a new numbered row
> when a load-bearing decision is made or changed; never rewrite history in place — supersede with a new
> entry that references the old one. The policy-model watch-items (plan §8) require a decision-log entry
> before the closed action vocabulary or condition enum is extended.

| # | Decision | Rationale | Alternatives rejected |
|---|---|---|---|
| D1 | New repo, new code; port Blogmill concepts only | Blogmill's substrate (globals, Express, MySQL, jQuery) is incompatible with Workers; its security posture is disqualifying | Incremental port (no viable path) |
| D2 | Collections as data, field types as code | Runtime content modeling is what makes MCP schema tools possible; field types need real code (validators, UI) | All-code schemas (Blogmill/Payload style — redeploy per change); all-data (nowhere for validation/UI logic to live) |
| D3 | Markdown-first rich text | Agent-legible, diff-able, portable; TinyMCE HTML blobs are the single most dated thing in Blogmill | HTML WYSIWYG (opaque to agents); Portable-Text-style JSON AST (heavier than v1 needs; revisit if block editing is wanted) |
| D4 | D1 + EAV index table for querying JSON content | Fixed schema stays tiny; dynamic fields can't use static columns; v1 query needs are modest | Per-collection tables w/ runtime DDL (migration hell); DO-SQLite-per-collection (complexity without a v1 payoff) |
| D5 | Single tenant, single site | Lightweight is the product; multi-tenancy multiplies auth, storage, and billing complexity everywhere | Multi-site (revisit only with a concrete need) |
| D6 | Headless-first; admin included, public rendering deferred | Admin is the product surface users touch daily; public rendering is cleanly separable as an API consumer | Bundled theme system v1 (Blogmill's scope trap) |
| D7 | Standalone single-package repo | dpt-platform's own monorepo platform layer is unwired stubs by its own admission | Adopting the dpt monorepo/turbo layout |
| D8 | Datastar SSR admin, no React | Proven in dpt-platform; tiny payload; islands cover the gaps (editor, uploads) | React/Next admin SPA (contradicts lightweight); HTMX (dpt already migrated off it) |
| D9 | Sessions for humans, bearer tokens for machines | Encrypted cookie needs no external store; tokens are revocable/scoped and MCP-friendly | JWT-everywhere (Blogmill's weak spot); OAuth provider (overkill single-tenant) |
| D10 | MCP via Cloudflare `agents` SDK on a DO | The supported Workers MCP path; DO gives session state | Hand-rolled MCP transport; premature tool-abstraction layer (dpt built one and deleted it) |
| D11 | R2 originals + variant-ready URL scheme; transforms deferred | `/media/:id/:variant` route shields consumers; Cloudflare Image Transformations can slot in without URL changes | Cloudflare Images/Stream from day one (cost/complexity before need) |
| D12 | Uppy for uploads | Maintained, excellent UX, direct-to-Worker multipart; the one Blogmill dependency worth keeping | Hand-rolled `<input type=file>` (poor resumability/progress) |
| D13 | CodeMirror 6 markdown island | Lightweight, no contenteditable fights, agents and humans see identical content | TinyMCE/Tiptap WYSIWYG v1 (heavy; revisit as an *additional* editor later) |
| D14 | Validation whitelist from field descriptors on every write path | Direct fix for Blogmill's mass-assignment vulnerability; one pipeline, three doors | Per-surface validation (drift guarantees a hole) |
| D15 | Humans and agents unified as principals; tokens belong to principals | One authorization pipeline; per-agent identity, revocation, and audit attribution; no shared keys | Separate "API key" model (unattributable writes); OAuth per agent (overkill single-tenant) |
| D16 | Default-deny, additive-only: RBAC (roles-as-data, scoped assignments, tiny condition enum) + per-item grants; no negative rules | Comprehensible and auditable; per-item precision without a policy language; "agent drafts, human publishes" falls out naturally | Full ABAC/policy DSL (complexity kills auditability); pure RBAC (no per-item control); external Zanzibar-style service (not lightweight) |
| D17 | Authorization enforced by witness types + SQL-compiled list filters | Bypassing `authorize()` is a compile error; paginated lists structurally can't leak (types/CI over convention) | Convention-only "services should check" (guarantees drift); in-memory post-filtering (leaks under pagination) |
| D18 | MCP served as a direct streamable-HTTP JSON-RPC endpoint (`src/mcp/handler.ts` + `tools.ts`), NOT an `agents`-SDK `McpAgent` on a Durable Object (supersedes D10's transport) | The `agents` SDK is a §8 fast-moving watch-item and its bearer-auth prop injection is version-fragile; a stateless, generated-tool server needs no DO session state. The load-bearing properties (tools generated from field descriptors, intersected with the principal's permissions, routed through the shared service pipeline) are preserved and unit-tested; the moving dependency stays contained to one thin module | `McpAgent` DO (couples MCP to a fast-moving SDK + adds DO session state for no gain here); a separate MCP worker (not lightweight, splits the one-pipeline invariant) |
| D19 | Personas as nullable `principals.subtype` ∈ {person, service, agent} — display/grouping only; security stays on `kind` (`user` \| `agent`) | Lets the UI distinguish a human, a data-pulling system, and an AI agent without touching the permission model; `refuseAgentEscalation` keys off `kind` and correctly covers services too; non-breaking backfill | A third security `kind` (ripples through every authorization decision for zero security gain); separate personas table (overkill for a display axis) |
| D20 | Email delivery behind an `EmailTransport` interface (`src/lib/email/`) with a console stub that logs redacted metadata + the action link — no real provider yet. *(Realized 2026-07-06: `ResendEmailTransport` selected when `RESEND_API_KEY` + a From exist; From precedence `settings.emailFrom` > `env.EMAIL_FROM`; styled templates in `src/lib/email/templates.ts`; stub remains the keyless/test default; sends are best-effort, never thrown.)* | Invite and share-by-email flows ship and are testable now; PII never logged; a provider (Resend/MailChannels) can be slotted in behind the same interface without touching callers | Blocking invites on provider selection; sending directly from services (untestable, unswappable) |
| D21 | Relations are `document_index` rows: the `relation` field's `toIndex` emits the target doc id(s), with the engine extended to allow one index row **per array element** — no separate edges table | One indexing path for all field types; backlinks are a reverse lookup on the same table the forward index already uses; multi-relations fall out of the same contract. *(Accepted; lands in roadmap Track B.)* | A dedicated `edges` table (second write path to keep in sync, second access story); storing arrays as JSON only (not reverse-lookupable) |
| D22 | Share links reuse `item_grants` with `subjectKind='link'` (hashed link token as `subjectId`; hashing per `src/lib/token.ts`) — no parallel permission system, and no migration (`subject_kind` has no CHECK constraint) | An outsider's read is decided by the same `getApplicableGrants`/`compileReadFilter` machinery as every other grant — expiry, revocation, and audit come free; the token is plaintext-once like API tokens | A separate share_links table + bespoke checks (parallel permission system — the exact smell A5 removed); signed URLs (no revocation) |
| D23 | Optional `ViewComponent` on the `FieldType` contract for read/detail/public surfaces, defaulting to safe escaped text; markdown renders via **micromark** (+GFM) — raw HTML escaped, dangerous protocols stripped, no separate sanitizer dep | The render seam stays inside the one field contract (the schema engine's seventh consumer, not a parallel template system); unsafe-by-default is impossible — only a type that opts in renders anything but escaped text; micromark is safe by construction on Workers (no DOM) | A template/theme engine (Blogmill's scope trap, D6); rendering in routes per collection (defeats schema-drivenness); `marked` + DOM-based sanitizer (DOMPurify needs a DOM shim on Workers) |
| D24 | Teams as a fourth item-grant subject kind (`subjectKind='team'`) backed by `teams`/`team_members`, plus multi-use expiring `team_invites` join links (`rmj_` tokens, role preset picked at mint, optional max-uses, expiry required ≤90d, principal created at acceptance) | "Share with the tech team" is subject RESOLUTION, not decision logic: membership resolves to `teamIds` beside `roleSlugs` in `subjectMatchFor`, so `decide()`, expiry, revocation, matrix visibility, and audit all come free; join links reuse the hash-at-rest/plaintext-once token discipline | Teams-as-roles (conflates capability with audience — a team must never carry permissions); widening `invite_tokens` (principal-bound `NOT NULL` FK + single-use `consumedAt` contradict a link whose principal doesn't exist yet) |
| D25 | A trusted `html` field type whose `ViewComponent` renders the value VERBATIM via `dangerouslySetInnerHTML` — the second sanctioned XSS exception (scoped reversal of D3's no-HTML-blobs stance for charts/visuals markdown can't express); trust = collection-level write permission (FieldAccess is reserved in v1), and the field is writable over REST/MCP by design | The platform's own authors (human or agent) are trusted to publish full pages with executable inline script under the public CSP; the exception stays inside the one field contract and is loudly documented at the type | A server-side sanitizer (no DOM on Workers — D23 — and it would strip exactly the scripts/SVG that motivate the feature); a separate "pages" subsystem outside the schema engine |
| D26 | New closed-vocabulary action `share_link`; `createShareLink` re-gated from `manage_access`+`refuseAgentEscalation` to `authorize('share_link', {collection, documentId})`; admin+editor system roles hold it; the MCP `share_link_<slug>` tool mints read-only links with a REQUIRED expiry clamped to 30 days | Link-minting is not access management: splitting it out lets a human grant an agent exactly "may share this" (via role or one-document item grant) while agents still never hold `manage_access` (SEC-8 untouched on every identity/role/token mutation); audit rows become self-describing (`share_link@mcp`) | A per-principal boolean flag (a parallel permission system outside roles/grants/scope); token-scope-only (the mask can only narrow — it cannot confer); leaving it under `manage_access` (all-or-nothing forces over-granting) |
| D27 | Per-collection `renderMode: 'shell' \| 'raw'` (raw = the first `html` field IS the standalone page, served via `c.html`, shell fallback when empty) + the security headers forked per surface: protected prefixes always strict; PUBLIC paths widen `script-src` to an exact CDN allowlist (jsdelivr/unpkg) only while the admin-settable, warning-labelled `allowCdnScripts` setting is on; Chart.js vendored under `/vendor/` so charts work with the toggle OFF | Full-page HTML needs the schema-level altitude (per-document flags would fragment rendering; global CSP widening would weaken the admin for a public-page feature); the prefix classifier + settings read is one PK lookup on public paths only | Global CSP widening (admin pays for a public feature); per-document render flags (wrong altitude); iframes/sandboxing (breaks the "the document IS the page" model) |
